# Design screen (`/customize/[productId]`)

The customer's configurator, laid out like a tailoring site: a large live preview on the left and the choices in tabs on the right. On phones the preview comes first, the tabs follow, and the size / price / cart bar stays pinned to the bottom.

| Part | File | What it does |
|---|---|---|
| Layout, state, save / cart | `app/(shop)/customize/[productId]/design-editor.tsx` | Holds the `DesignSpec` (the source of truth), undo/redo, the preview and the tabs. All tab panels stay mounted (hidden when inactive), so the AI box keeps polling and nothing resets on a tab switch. |
| Preview | `design-canvas.tsx`, `recolor.ts` | Fabric.js canvas over the recoloured garment picture for the chosen style (`garmentPicture()`, the same choice as the server renderer). For photo templates the picture is the dress's real photo or an AI style picture; when no picture shows the exact style yet, the closest one is used and a note says so. A tool rail has Undo, Redo, See it on me (the realistic AI try-on) and Live mirror (the camera, on the device: [live-try-on.md](live-try-on.md#the-live-mirror)); front/back thumbnails switch sides. The canvas passes its garment-with-printed-items picture up (`onPrinted`), so the mirror shows the design as drawn. Printed items are shown shaped by the fabric (wrap, folds, light; `fabricFieldFor()` and `applyFabricField()`, see [rendering.md](rendering.md#how-a-side-is-composed)): the canvas objects are invisible handles, and their flattened, shaped pixels are drawn into the background with the garment. While an item is dragged, scaled or rotated it shows semi-transparent on top, so it can be placed precisely. Only the active print area is outlined. |
| Fabric tab | `fabric-tab.tsx` | Pick a part (whole garment or one region; hidden when there's only one), then a fabric tile: the template's plain colours, then each allowed pattern on each colour (printed in the most contrasting allowed colour, adjustable under "Pattern colour"). **All-over print** below it repeats a decoration (any allowed colour) or the customer's uploaded image across the chosen part(s), with a size slider (repeats every 3–30 cm). |
| Style tab | `style-tab.tsx` | A row per group (Neckline, Sleeves, Length) opening into picture tiles with prices. Tiles show the admin's reference image, or a line drawing from `lib/catalog/style-icons.ts` matched by option id. |
| Decoration controls | `decoration-controls.tsx` | For a selected decoration: second colour (shapes with a detail), Filled/Outline with thickness, Mirror, and "Repeat as a border" with how many (2–24), spacing and curve. Selected images (uploads and cut-outs) get Mirror and the same border controls (`ImageControls`). Changing them resizes the box with `borderBox` (keeps the centre and motif size, grows taller for a curve, stays inside the area, and within the middle 60% of areas trimmed to the fabric). |
| Cut-out dialog | `cutout-dialog.tsx`, `cutout-actions.ts` | "From another dress": the customer's earlier cut-outs, then a live ClothSeeker dress, a box dragged on its photo, "Remove fabric" (strength), **Cut out**, up to 4 colour swaps from this design's colours ("Apply colours" cuts again), and **Use on my design** (an image layer, priced as a decoration). Signed-out visitors are sent to sign in. See [design-spec.md](design-spec.md#decorations-taken-from-other-dresses). |
| Personalise tab | `personalise-tab.tsx` | Print area (on the demo items: the whole front, each part or the whole back, trimmed to the fabric), text, decorations, decorations from another dress and the customer's own image (new items start at a sensible size and in the allowed colour that contrasts most with the fabric), plus the controls for the item selected on the canvas (picking an item on the canvas opens this tab). |
| AI ideas tab | `ai-box.tsx` | The AI design box ([ai-pipelines.md](ai-pipelines.md)). A design started from a description opens on this tab. |
| Shared pieces | `editor-ui.tsx` | Tiles, accordion rows, swatches, rail buttons, side thumbnails. |

Prices and validation on this screen are previews: the server recomputes both on save, cart and checkout ([design-spec.md](design-spec.md)). A pattern costs its add-on once per part, so a patterned whole dress counts each region.

Browser tests reach the tabs through `openDesignTab()` and fabrics through `chooseFabric()` in `tests/e2e/helpers.ts`.
